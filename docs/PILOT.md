# Pilot and public release checklist

## Team trial

Use a consenting group and a private test repository first. Tell participants what is collected and who can read it. Do not contact other teams without their agreement.

- Record a declaration, correct it, then remove it. Verify another person cannot modify it.
- Try outsider commands and a bot comment; neither should act.
- Squash-merge a PR whose original commits have an AI trailer; check the separate evidence section.
- Compare the activity report with GitHub and note missing history or identity aliases.
- Copy the bounded draft into the official university form. Ask students whether all five reflection fields are understandable, and confirm the absent Part E with the assessor.
- Restart the host, verify persistence, remove installation access and verify cleanup.
- Capture confusion, time taken, inaccuracies and requested changes. Avoid treating commit totals as marks.

## Before public sharing

Set the support contact and actual retention policy, complete the deployment smoke tests and review the documented scale/rename limitations. Add a sanitized demo screenshot and installation URL to the README. Make the production app public only when ready.

Marketplace is optional and is not submitted. A future submission requires checking current GitHub requirements, preparing a logo, feature image and screenshots, and completing GitHub's review. Do not promise listing approval or monetize before the pilot establishes value.
